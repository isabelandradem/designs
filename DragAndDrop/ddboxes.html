First, what is a “Boxes” drag?

DDBoxes is the first of the Family 2 “Boxes” types. Boxes drags feel a little different from the slot-based drags in Family 1:

Family 1 · Slot-Based dragsFamily 2 · Boxes drags
Feel Drop an item into a drop slot; the question often checks immediately. Arrange items in a row of Boxes-style drop slots; the child can rearrange before submitting.
Swapping Generally one drop, done. Dropping onto a full drop slot swaps the item already there back to the tray.
Checking the answer Often checks the moment the last item lands. Child arranges everything, then taps the green submit button to check.

Why this matters for you

Boxes types are great when children should be able to try, rethink, and rearrange before committing — spelling a word, copying a pattern, or ordering items. The green button lets them decide when they’re done.

How DDBoxes works

DDBoxes shows a row of Boxes-style drop slots. Each drop slot has a matching Valid item. The child drags items into the drop slots, rearranges as needed, and presses the button to check. The answer is correct when every required drop slot holds an accepted Valid item.

The one rule that defines DDBoxes

Each drop slot has a specific accepted Valid item. A Valid item’s slot says which drop slot (or slots) accepts it. This is a matching-to-drop-slots task, checked when the child submits.

Key fields you’ll set

FieldWhat it does
questionTypeAlways "DDBoxes" for this type.
layoutThe visual template — how many drop slots and where the tray sits.
numTotalItemsHow many draggable items appear (Valid + Bogus).
numValidItemsHow many drop slots must be filled with accepted Valid items.
showSubmitButtontrue shows the green “done” button. Boxes questions usually check on submit.
dropSlotStyleLook of the drop slots, e.g. "DashBorder" draws a dashed outline.
var1, var2…Reusable values swapped into image paths.
soundExtWhich audio version plays on tap (e.g. "_word").

Item types inside items

itemTypeMeaning
ValidA draggable item accepted by a drop slot. Its slot names the accepted drop slot(s), e.g. "drop1" or "1,3".
BogusA draggable item that isn’t accepted by any drop slot.
StaticA fixed picture — a reference word, drop slot art, or an item already placed in a drop slot.
DropDefines a drop slot itself (position/size).
BackgroundThe full-screen background image.
InstructionWhat Kodi says/asks.
Yay / OopsThe correct / incorrect feedback (text + audio).
ThisIsHowThe “let me show you” demonstration after repeated misses.

5.1 One drop slot per Valid item

The straightforward case: each Valid item is accepted by exactly one drop slot. The child figures out which item goes in which drop slot, arranges them, and submits.

5.2 Multiple accepted drop slots per Valid item

When several drop slots should accept the same item, that item can be valid in more than one drop slot. Use a comma-list on the Valid item’s slot to say “any of these drop slots accepts this item.”

The yellow monster is "slot": "1,3" — accepted by drop slot 1 or 3. The red monster is "slot": "2,4" — accepted by drop slot 2 or 4. itemSlot: "1,2" just sets the tray positions (two yellow copies, two red). The pattern to copy is shown as Static monsters up top, and showSubmitButton: true gives the green check button.

Quick recap

5.1 each Valid item → one accepted drop slot · 5.2 a Valid item can be accepted by several drop slots (comma-list slot). Across both, DDBoxes is a matching-to-drop-slots task that the child confirms with the green button.
