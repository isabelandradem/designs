How it works

DDFillBoxes is the same as DDBoxes in every way that matters for the answer: a row of drop slots, each with an accepted Valid item. The one added behavior is that when an item is dropped into a slot, it resizes to fill that drop slot (and shrinks back to its normal size if pulled out).

The one rule that defines DDFillBoxes

The drop slot controls the size. Whatever you drop snaps to fill the drop slot, so every placed item looks consistent — handy when your items have different natural sizes.

vs DDBoxes

These two are interchangeable for grading — the difference is purely visual:

DDBoxesDDFillBoxes
Dropped item size Keeps its own size (its scale). Resizes to fill the drop slot.
Who controls the size The item. The drop slot.
Matching, swapping, submit button Identical in both

Which should you pick?

Choose DDFillBoxes when items have different shapes/sizes and you want them all to fit their drop slots uniformly (pictures into frames, panels into a row). Choose DDBoxes when items are already box-sized and should keep their own size. Switching between the two is just a one-word change to questionType.

Key fields you’ll set

FieldWhat it does
questionTypeAlways "DDFillBoxes" for this type.
layoutThe visual template — how many drop slots and where the tray sits.
numTotalItemsHow many draggable items appear (Valid + Bogus).
numValidItemsHow many drop slots must be filled with accepted Valid items.
dropSlotStyleLook of the drop slots, e.g. "DashBorder" draws a dashed outline.
bgPath (on an item)A background behind the item (e.g. a white square) so it reads as a clean tile inside the drop slot.
itemSlot (on an item)Which tray position the item starts in (so it doesn’t start already in order).

Item types inside items

itemTypeMeaning
ValidA draggable item accepted by a drop slot. Its slot names the accepted drop slot; it will resize to fill that slot.
BogusA draggable item that isn’t accepted by any drop slot.
StaticA fixed picture — a label, arrows between drop slots, or drop slot art.
DropDefines a drop slot itself (position/size). This size is what items fill to.
BackgroundThe full-screen background image.
InstructionWhat Kodi says/asks.
Yay / OopsThe correct / incorrect feedback (text + audio).

6.1 Fill the drop slots in order

A sequencing task: the child puts story pictures in the right order across a row of drop slots. Each picture belongs in one drop slot (slot: "1", "2", "3"), and because the panels are cropped differently, DDFillBoxes makes them all fill their drop slots uniformly.

Each story panel has its accepted drop slot — slot: "1", "2", "3" (the right order) — while itemSlot shuffles their starting positions in the tray (3, 1, 2) so the child has to reorder them. The panels are cropped differently, so DDFillBoxes resizes each to fill its drop slot for a tidy, even row. The Static arrows (stat1,stat2) sit between the boxes to show left-to-right order.

Good to know

This exact question would also work as DDBoxes — the grading is the same. The author chose DDFillBoxes so the differently cropped story panels all fill their drop slots uniformly. That’s the whole difference.

6.2 Measure on a ruler

Here there’s just one drop slot at the top of a ruler and several items to try. The child drags each item onto the ruler to see how long it is, and leaves the Valid item in place. Because the items are different lengths, DDFillBoxes keeps the dropped item sized to the drop slot so it lines up cleanly with the ruler.

There’s a single drop slot (drop1), defined by the Drop item and backed by the ruler Static. The Valid straw is accepted by it (slot: "drop1"), while the Bogus item supplies the two Bogus items (pencil + paintbrush) — note one Bogus entry can list several pictures. numValidItems: 1 means only one drop slot needs a Valid item. The child can freely try each item on the ruler; it snaps to fill the drop slot so it aligns with the inch marks.
