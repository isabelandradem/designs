How it works

In a DDXintoA question, the screen has draggable items and one drop slot group. Some items are Valid and some may be Bogus. The child drags the required number of Valid items into the drop slot. A Bogus drop triggers the Oops.

The one rule that defines DDXintoA

There is one accepted drop slot group. Whether the layout shows one visible drop slot or several possible drop slots, the goal is to get the Valid item(s) into the accepted slot.

Key fields you’ll set

These are the settings at the top of each question that control the behavior.

FieldWhat it does
questionTypeAlways "DDXintoA" for this type.
layoutThe visual template — where the drop slot(s) and tray sit on screen.
numTotalItemsHow many draggable items appear in the tray.
numValidItemsHow many Valid items must be dragged into the drop slot.
numExtraItemsExtra items beyond the layout’s usual count (used by the fishbowl).
dropSlotStyleLook of the drop slot, e.g. "DashBorder" draws a dashed outline.
showSubmitButtonfalse = checks automatically on drop. true = child taps a button when done.
var1, var2…Reusable text/word values swapped into image paths (e.g. {var1}).
disableTurns off features (e.g. oops, scaling, sparkles).

Item types inside items

Each entry in the items list is one piece of the screen. The itemType tells the app what it is.

itemTypeMeaning
ValidA draggable item that counts toward the answer. Its slot says which drop slot accepts it.
BogusA draggable item that does not count toward the answer.
StaticA fixed picture that doesn’t move — a label, a reference item, or art aligned to a stat or drop slot.
DropDefines the drop slot itself (position/size, e.g. drop1).
BackgroundThe full-screen background image.
InstructionWhat Kodi says/asks. Multiple lines provide re-read variations.
Yay / OopsThe correct / incorrect feedback (text + audio).
ThisIsHowThe “let me show you” demonstration after repeated misses.

1.1 Several drop slots — only one accepts the Valid item

The layout shows more than one drop slot, but only one accepts the Valid item. The accepted drop slot is set by the Valid item’s slot (for example "drop2") — that is the only drop slot that counts.

1.3 Several items — more than one Valid item, one drop slot

Same single drop slot, but now several items are Valid and all of them go into that drop slot. The child must drag in every Valid item. Set numValidItems to the number of Valid items, and give each Valid item the same slot (e.g. drop1).

1.4 One drop slot — drag a set number of items (fishbowl)

One drop slot (a fishbowl), and the child drags in a specific count of items. Here numValidItems is how many to put in, and numExtraItems adds extra identical toys to drag from. Because there’s no single required item identity — just the required count — the child taps a green submit button to say they’re finished. This variant uses a behaviorStyle (the special Fishbowl animation).

Quick recap of the four shapes

1.1 many drop slots, one accepts the Valid item · 1.2 many items, one Valid · 1.3 many items, several Valid · 1.4 one drop slot, a set number of items. In every case there is still one accepted drop slot group — that’s what makes it DDXintoA.
